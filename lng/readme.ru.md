# Система локализации AQI Notifier (v2.1)

Система основана на **рекурсивном блочном шаблонизаторе** с поддержкой логики на стороне шаблонов.

---

## 1. Основной принцип: Логика в шаблонах
Мы полностью отказались от формирования иконок, заголовков и списков в Go-коде. Весь UI строится в JSON на основе "сырых" данных.

### 1.1. Вложенные условия (Switch)
Если третья часть условия (else) начинается со знака `?`, она трактуется как вложенный условный оператор. Это позволяет создавать цепочки `switch`.

**Пример:**
```json
"txtAlertHeader": "@?isAlert%@icoAlert@ ВНИМАНИЕ%?isNorma%@icoSuccess@ НОРМА%@icoInfo@ ИНФО@@"
```

---

## 2. Атомарные данные (из Go-кода)
Бот передает только чистые данные и флаги состояний.

| Плейсхолдер | Описание |
| :--- | :--- |
| @aqiLevel@ | Уровень AQI (1-7). Используется для сборки ключа иконки: `@icoLevel@aqiLevel@@`. |
| @isAlert@ | Флаг наличия критического предупреждения (bool). |
| @isNorma@ | Флаг восстановления нормы (bool). |
| @evt_name_id@ | Флаги активных событий (например, @evt_val10_yu@). |
| @aqiVal@, @val25@... | Численные показатели. |

---

## 3. Отказ от виртуальных холдеров
Запрещено использовать холдеры типа `@icon@`, `@title@`, `@alerts@`, так как их содержимое формируется в коде. 
Вместо них используйте логические блоки в JSON:
- Для иконок: `@icoLevel@aqiLevel@@`.
- Для заголовков: условный оператор по `isAlert` / `isNorma`.
- Для списков: цепочка условий по флагам событий `evt_...`.

---

## 4. Правила оформления
1. **Никакого Unicode-экранирования**: Только нативный HTML (`<b>`, `<i>`) и текст.
2. **Иерархическая сортировка**: Ключи сгруппированы по темам (Мастер-шаблоны -> Компоненты -> Кнопки -> Системные).
