# Формат Partial Refresh (epd_pr)

Данный документ описывает механизм инкрементального (частичного) обновления экранов EPD (Electronic Paper Display). Режим `epd_pr` позволяет значительно сократить объем передаваемых данных и устранить мерцание всего экрана за счет передачи только тех областей (тайлов), которые изменились по сравнению с предыдущим кадром.

## Как это работает

1. **Кеширование**: Сервер хранит в памяти (`image.Image`) последний сгенерированный кадр для каждого подключенного устройства. Идентификация устройства происходит по параметру `mac` в URL.
2. **Определение разницы**: При новом запросе сервер генерирует свежий кадр и сравнивает его со старым кадром из кеша.
3. **Разделение на блоки**: Поиск отличий происходит по сетке **8x8 пикселей**. Использование сетки 8x8 гарантирует, что координаты и ширина всех тайлов будут кратны 8. Это идеально выравнивает пиксели по границам байтов, исключая необходимость сложных побитовых сдвигов на стороне клиента.
4. **Bounding Boxes**: "Грязные" (изменившиеся) блоки 8x8 объединяются в прямоугольные зоны (тайлы) минимального размера.
5. **Упаковка**: Каждый такой прямоугольный тайл запаковывается в битовый поток и отправляется клиенту единым бинарным пакетом.

## Примеры запросов

Режим `epd_pr` задается в конфигурационном `.yaml` файле дашборда (`format: "epd_pr"`).
Для работы кеша устройство должно передавать свой идентификатор (MAC-адрес).

### Стандартный запрос
```http
GET /dashboard.yaml?mac=AA:BB:CC:DD:EE:FF
```
- Если сервер имеет предыдущий кадр для этого MAC-адреса, он вернет **только изменившиеся тайлы**.
- Если старого кадра нет (первый запуск клиента или перезапуск сервера), сервер вернет **1 полноэкранный тайл**, который полностью покрывает дисплей.

### Принудительное полное обновление
```http
GET /dashboard.yaml?mac=AA:BB:CC:DD:EE:FF&force_full=true
```
- Сервер проигнорирует кеш, обновит его текущим кадром и принудительно вернет 1 полноэкранный тайл. Это полезно для периодической очистки EPD-матрицы от артефактов (ghosting).

## Бинарный протокол (Little-Endian)

Независимо от того, является ли обновление полным или частичным, ответ сервера всегда представляет собой последовательность тайлов.
**Важно:** Все многобайтовые числа передаются в формате **Little-Endian** (младший байт вперед), что является нативным форматом для микроконтроллеров архитектуры ESP32/Xtensa/ARM.

### Структура ответа

| Смещение | Размер | Тип данных | Описание |
| :--- | :--- | :--- | :--- |
| `0x00` | 2 байта | `uint16_t` | `N` — Общее количество тайлов в пакете |
| `0x02` | ... | Тайлы | Данные для `N` тайлов (идут друг за другом) |

### Структура каждого тайла

Каждый тайл начинается с 8-байтового заголовка, за которым следуют запакованные пиксели.

| Размер | Тип данных | Описание |
| :--- | :--- | :--- |
| 2 байта | `uint16_t` | `X` — Координата тайла по горизонтали (от левого края экрана) |
| 2 байта | `uint16_t` | `Y` — Координата тайла по вертикали (от верхнего края экрана) |
| 2 байта | `uint16_t` | `W` — Ширина тайла в пикселях |
| 2 байта | `uint16_t` | `H` — Высота тайла в пикселях |
| `M` байт | `uint8_t[]` | Данные пикселей (bitplane формат) |

### Вычисление размера данных (M)

Так как ширина `W` гарантированно кратна 8, количество байтов для пиксельных данных тайла рассчитывается элементарно:

$$ M = \frac{W \times H \times BPP}{8} $$

*Где `BPP` (Bits Per Pixel) — количество бит на пиксель (например, 2 бита для 4-х цветов).*

### Пример ответа сервера

**Сценарий:** Изменились только показания времени в небольшой прямоугольной области экрана.
Допустим, время отрисовалось на координатах `X=16`, `Y=32` и заняло область шириной `W=64` и высотой `H=16`. У нас дисплей с палитрой 4 цвета (BPP=2).

Размер данных тайла: `(64 * 16 * 2) / 8 = 256 байт`.

Бинарный дамп ответа (в HEX):
```
01 00                   // Количество тайлов: 1 (Little-Endian)

// ТАЙЛ 1
10 00                   // X = 16 (0x0010)
20 00                   // Y = 32 (0x0020)
40 00                   // W = 64 (0x0040)
10 00                   // H = 16 (0x0010)
[ ... 256 байт данных пикселей тайла ... ]
```

### Пример обработки на C/C++ (ESP32)

Пример псевдокода для приема пакета `epd_pr` и отрисовки его на экране:

```cpp
// 1. Читаем количество тайлов (2 байта, Little-Endian)
uint16_t num_tiles;
read_from_socket(sock, &num_tiles, sizeof(num_tiles));

// 2. Обрабатываем каждый тайл
for (int i = 0; i < num_tiles; i++) {
    uint16_t x, y, w, h;
    
    // Читаем заголовок тайла (8 байт)
    read_from_socket(sock, &x, sizeof(x));
    read_from_socket(sock, &y, sizeof(y));
    read_from_socket(sock, &w, sizeof(w));
    read_from_socket(sock, &h, sizeof(h));
    
    // Считаем размер данных тайла. Для 2-bit (4 цвета) BPP=2.
    // Т.к. W кратно 8, деление на 4 всегда происходит без остатка.
    size_t data_size = (w * h) / 4; 
    
    // Выделяем память под данные тайла
    uint8_t* buffer = (uint8_t*)malloc(data_size);
    if (buffer) {
        // Читаем данные пикселей
        read_from_socket(sock, buffer, data_size);
        
        // Отправляем буфер в драйвер дисплея для частичного обновления
        epd_draw_partial(x, y, w, h, buffer);
        
        free(buffer);
    }
}

// Применяем изменения (refresh) если драйвер этого требует
epd_update_screen();
```
