# Документация системы локализации AQI Notifier

> 🇬🇧 [English version](readme.en.md)

Система локализации бота AQI Notifier построена на базе **рекурсивного блочного шаблонизатора** с поддержкой логики на стороне шаблонов. Это позволяет полностью отделить логику отображения (иконки, тексты, структуру сообщений) от программного кода.

---

## 1. Базовый синтаксис

### 1.1. Плейсхолдеры
Основной формат: `{key%format}`
- `key`: Имя ключа в JSON или имя переменной, переданной из Go.
- `format`: Опциональный модификатор (форматирование чисел, дат или регистра).

### 1.2. Рекурсивное разрешение
Если значение ключа содержит другие плейсхолдеры, они будут разрешены рекурсивно.
**Пример:**
`"txtDevice": "{icoDevice} {deviceName}"`
Шаблонизатор сначала найдёт `icoDevice` в словаре, затем подставит переменную `deviceName`.

### 1.3. Модификатор `%raw`
Если значение плейсхолдера уже является готовым HTML или текстом, которое не нужно экранировать и не нужно искать в словаре, используется модификатор `%raw`:
`"{correctionsList%raw}"` — вставляет значение переменной «как есть», без дополнительной обработки.

## 2. Условные конструкции (Логика)

Синтаксис: `{?condition%true_text%false_text}`

### 2.1. Операторы сравнения
| Оператор | Алиасы | Описание |
| :--- | :--- | :--- |
| `==` | `eq` | Равно |
| `!=` | `ne` | Не равно |
| `>` | `gt` | Больше |
| `<` | `lt` | Меньше |
| `>=` | `ge` | Больше или равно |
| `<=` | `le` | Меньше или равно |
| `isEmpty` | - | Истина, если значение пустое или 0 |
| `isNotEmpty` | - | Истина, если значение не пустое |

### 2.2. Вложенные условия (Switch)
Если `false_text` начинается с `?`, он обрабатывается как следующий уровень условия.
**Пример:**
`"txtHeader": "{?isAlert%{icoAlert} ВНИМАНИЕ%{?isNorma%{icoBackToNorm} НОРМА%{icoInfo} ИНФО}}"`

### 2.3. Условный блок (block-if)
Синтаксис: `{?boolVar%content_if_true%}`
Если нужен только ветка «истина», ветку «ложь» можно оставить пустой.
**Пример:**
`"{?hasCorrections%Корректировка значений:\n{correctionsList%raw}\n\n%}"` — блок отображается только при наличии корректировок.

## 3. Модификаторы форматирования

### 3.1. Регистр (Case Formatters)
- `%toUpper`: ПЕРЕВОДИТ В ВЕРХНИЙ РЕГИСТР
- `%toLower`: переводит в нижний регистр
- `%toTitle`: Делает Первую Букву Заглавной

### 3.2. Числа (printf)
Используется синтаксис Go:
- `%.1f`: 12.3
- `%.2f`: 12.34
- `%+0.1f`: +12.3 (с принудительным знаком)
- `%d`: 123

### 3.3. Дата и время
Время автоматически форматируется в **локальном часовом поясе** сервера.
- `%02.01.2006`: 02.05.2024
- `%15:04:05`: 14:30:05

## 4. Справочник плейсхолдеров (Go → JSON)

### 4.1. Общие переменные (доступны в `msgStatus`, `msgAlertNotify` и др.)
- `{date}`, `{time}`: Объект времени измерения (всегда локальное время).
- `{deviceId}`: Технический ID устройства.
- `{deviceName}`: Имя устройства (пользовательское или «Устройство <ID>»).

### 4.2. Показатели PM2.5 и PM10
- `{val25}`, `{curr25}`: Текущее значение PM2.5.
- `{prev25}`: Предыдущее значение PM2.5 (до изменения).
- `{diff25}`: Абсолютная разница (`curr - prev`).
- `{diff25Percent}`: Процентное изменение.
- `{trend25Icon}`: Иконка тренда (📈, 📉, ➖).
- `{zone25Icon}`: Иконка зоны загрязнения (🟩, 🟨, 🟥).
- `{labelPm25}`: Локализованная подпись («PM2.5»).
- `{unitPm}`: Единица измерения («мкг/м³»).
- *(Аналогично для PM10: `{val10}`, `{curr10}`, `{prev10}`, `{diff10}`, `{diff10Percent}`, `{trend10Icon}`, `{zone10Icon}`, `{labelPm10}`)*

### 4.3. Показатели AQI (Air Quality Index)
- `{aqiVal}`: Численное значение индекса.
- `{aqiLevel}`: Номер уровня (1–7).
- `{aqiIcon}`: Цветная иконка уровня (🟢, 🟡, 🟠, 🔴, 🟣, 🟤, ⚫).
- `{aqiName}`: Название уровня («Хорошо», «Умеренно» и т.д.).
- `{aqiStandardFlag}`: Флаг выбранного стандарта (🇪🇺, 🇺🇸, 🇨🇳).

### 4.4. Метеоданные
- `{valT}`: Температура (в °C или °F).
- `{labelT}`: Подпись («Температура»).
- `{unitT}`: Единица («°C» или «°F»).
- `{valH}`: Влажность (%).
- `{labelH}`: Подпись («Влажность»).
- `{valDp}`: Точка росы (рассчитанная).
- `{labelDp}`: Подпись («Точка росы»).
- `{valP}`: Давление (в мм.рт.ст. или гПа).
- `{labelP}`: Подпись («Давление»).
- `{unitP}`: Единица («мм.рт.ст.» или «гПа»).

### 4.5. Переменные состояний (только для `msgAlertNotify`)
- `{isAlert}`: `true`, если есть хотя бы одно событие ухудшения.
- `{isNorma}`: `true`, если воздух вернулся в норму.
- `{isSilent}`: `true`, если уведомление без звука.
- `{isRise}`: `true`, если уровень (AQI или PM) повысился.
- `{isFall}`: `true`, если уровень понизился.
- `{isReturn}`: `true`, если произошло возвращение в чистую зону.
- `{isSharp}`: `true`, если сработал триггер резкой динамики.
- `{isAqi}`, `{isPm25}`, `{isPm10}`, `{isBoth}`: Определяют тип сработавшего события.
- `{isRed}`, `{isYellow}`, `{isGreen}`: Приблизительная зона сработавшего события (L3, L2, L1).
- `{evt<EventID>}`: Динамические флаги всех произошедших событий (например, `{evtAqiL2}`, `{evtVal25L3u}`, `{evtDiff10Rise}`).

### 4.6. Настройка порогов (`msgAqiCycleMenu`, `msgThresholdsMenu`, `msgResetConfirm`)
- `{l1_25}`, `{l2_25}`: Пороги уровня 1 и 2 для PM2.5.
- `{dyn25}`: Порог динамики (%) для PM2.5.
- `{l1_10}`, `{l2_10}`: Пороги уровня 1 и 2 для PM10.
- `{dyn10}`: Порог динамики (%) для PM10.

### 4.7. Настройки устройства (`msgDeviceSettings`, `msgDeviceSettingsCorrItem`)
- `{type}`: Отображаемое название типа датчика (например, «ArmAQI (SDS011)»).
- `{hasCorrections}`: `true`, если для типа устройства заданы формулы коррекции.
- `{correctionsList%raw}`: Готовый HTML-список строк коррекции (вставляется как `%raw`).

Для шаблона одной строки коррекции (`msgDeviceSettingsCorrItem`):
- `{key}`: Человекочитаемое название показателя (берётся из ключа `labelField_<поле>`).
- `{formula}`: Уже отформатированная формула в виде строки.

Для шаблона тернарной формулы (`msgFormulaTernary`):
- `{cond%raw}`: Условие тернарного оператора.
- `{trueVal%raw}`: Значение при истинном условии.
- `{falseVal%raw}`: Значение при ложном условии.

## 5. Система ресурсов и конфигураций (`res/`)

Файлы в папке `res/` определяют визуальное оформление и логику расчёта стандартов качества воздуха.

### 5.1. Цвета (`colors.json`)
Централизованный справочник цветовых кодов.
- **Назначение**: Используется для отрисовки графиков и как источник значений для плейсхолдеров цветов.
- **Использование**: В `aqi.json` или других ресурсах можно ссылаться на цвета через `{colorName}`. Это позволяет менять палитру всего приложения в одном файле.

### 5.2. Иконки (`ico.json`)
Глобальный словарь эмодзи и графических символов.
- **Назначение**: Отделение графики от текста. Все иконки доступны в шаблонах как плейсхолдеры `{icoName}`.
- **Гибкость**: Позволяет быстро менять визуальный стиль без правки логики или текстовых шаблонов.

### 5.3. Стандарты AQI (`aqi.json`)
Определяет правила расчёта индекса и границы зон для различных регионов (US, EU, CN). Является «единственным источником правды» для математической модели AQI.
- **Основные поля**:
    - `tag`: Код стандарта (`Us`, `Eu`, `Cn`).
    - `indexPoints`: Точки шкалы индекса (IAQI).
    - `breakpoints25` / `breakpoints10`: Пороговые значения концентраций PM.
    - `zones`: Описание уровней (уровень, название, цвет, иконка).

### 5.4. Механизм переопределения (Overrides)
Бот поддерживает динамическое переопределение данных из `aqi.json` через файлы локализации и иконок. Это позволяет адаптировать стандарт под разные языки (например, склонять названия зон). Порядок поиска:
1. **Флаги**: Ключ `icoFlag<TAG>` в `ico.json`.
2. **Иконки уровней**: Ключ `icoAqi<TAG>Level<N>` в `ico.json`.
3. **Названия уровней**: Ключ `aqiNameL<N><Tag>` в словаре (`ru.json`).
4. **Названия стандартов**: Ключи `standard<Tag>` (полное) и `txtStandard<Tag>` (краткое).

*Если специфичный ключ не найден в локализации, используются значения по умолчанию из `aqi.json`.*

## 6. Правила разработки

1. **Никакой логики в Go**: Запрещено формировать списки или выбирать иконки в коде. Используйте `evt*` флаги и условные операторы в JSON.
2. **Именование**: Всегда `camelCase` для ключей и переменных.
3. **HTML**: Используйте нативные теги `<b>`, `<i>`, `<code>`.
4. **Unicode**: Запрещено использование Unicode-экранирования (`\u003c`) в JSON-файлах.
5. **Сортировка**: Ключи в JSON должны быть отсортированы тематически.
6. **`labelField_<поле>`**: Для любого нового показателя (pm01, co2 и т.д.) обязательно добавить соответствующий ключ `labelField_<поле>` в каждый языковой файл.
